# Database Lab 4: Stored procedures

Assignment: `sp_Assingment.pdf` (5 procedures on Pubs, 5 on Northwind) and `instruction.txt`
(Word report, a full screenshot under every script, comments in every script, Pubs converted
from MS SQL Server to PostgreSQL).

## Files

| File | Contents |
|---|---|
| `pubs/instpubs.sql` | Microsoft's original pubs script (MS SQL Server), unchanged |
| `pubs_postgres.sql` | Pubs converted to PostgreSQL 16, generated by `scripts/convert_pubs.py` |
| `pubs_procedures.sql` | Pubs tasks 1–5 and a conversion check, with demo calls |
| `northwind_procedures.sql` | Northwind tasks 1–5, with demo calls |
| `results/` | Real psql output of both files and of every demo (`python scripts/save_results.py`) |
| `screenshots/` | Your screenshots, one per demo (see below) |
| `23B1NUM1470_Дугаржанцан_Билгүүн_StoredProcedure.docx` | The Word report |

Both procedure files run from start to finish with `psql -v ON_ERROR_STOP=1`. Error demos are
wrapped in `DO` blocks that print the message as a `NOTICE`, and data-changing demos run inside
`BEGIN ... ROLLBACK`, so the databases stay unchanged.

## Environment

Same portable PostgreSQL 16.15 as lab 3 (`localhost:5432`, user `dedibeat`, no password).
Run these from the `lab4` folder:

| Command | Purpose |
|---|---|
| `scripts\db.cmd start` | Start PostgreSQL |
| `scripts\db.cmd init-pubs` | (Re)create the `pubs` database and load `pubs_postgres.sql` |
| `scripts\db.cmd check` | Show Pubs row counts |
| `scripts\db.cmd connect pubs` / `connect northwind` | Open `psql` |
| `scripts\db.cmd run pubs` / `run northwind` | Run `pubs_procedures.sql` / `northwind_procedures.sql` |
| `python scripts\convert_pubs.py` | Regenerate `pubs_postgres.sql` from `pubs/instpubs.sql` |
| `python scripts\save_results.py` | Save every result to `results/` |
| `python scripts\build_report.py` | Rebuild the Word report (`--pdf` also writes a PDF preview) |

`dedibeat` has no `CREATEDB` right, so `init-pubs` creates the empty database as the `postgres`
superuser with `dedibeat` as the owner, then loads the script as `dedibeat`.

## Screenshots

The report has a slot under every demo script. Each slot names its file, for example
`screenshots/pubs_1_1.png` for "Example 1.1" in `pubs_procedures.sql` and
`screenshots/northwind_2_3.png` for "Example 2.3" in `northwind_procedures.sql`. To fill them:

1. Open the `lab4` folder in VS Code. The SQLTools connections **Lab 4 Pubs** and
   **Lab 4 Northwind** are in `.vscode/settings.json`.
2. Select one demo (from its `-- Example` comment to the next one), run it, and take a full-screen
   screenshot. Save it under the name the slot shows. Extra images for the same demo go in
   `pubs_1_1_2.png`, `pubs_1_1_3.png`, ...
3. Run `python scripts\build_report.py`. It puts every screenshot it finds into its slot and
   lists the ones still missing.

Notes:

- Select the whole demo, including `BEGIN` and `COMMIT`/`ROLLBACK`. Procedures that return a list
  hand back a cursor that only lives until the end of that transaction.
- `DO` blocks print their message as a `NOTICE`, which SQLTools shows in its SQL Console panel.
- `results/txt/<demo id>.txt` has the expected output of each demo, to compare with what you see.
- Pubs demo 5.2 creates an order number from the current time (`TRF-YYMMDDhhmmss`), and the
  `MC3026`/`PC9999` publication dates are the date `pubs` was loaded (the original script leaves
  them to `GETDATE()`), so those values differ from run to run.
- If you paste screenshots into Word by hand instead, right-click the table of contents and
  choose **Update Field** afterwards so the page numbers are right.
